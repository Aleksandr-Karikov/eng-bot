# AGENTS.md — как работать в этом репозитории

Инструкции для агентов и людей, которые правят код. Что делает бот и как его запустить — в `README.md`.
Здесь — только то, что легко нарушить и трудно заметить.

## Команды

```bash
npm test          # vitest run — 93 файла, ~16 с (SQLite in-memory, сеть и LLM не нужны)
npm run typecheck # tsc --noEmit — тоже обязательно
npm run db:generate  # drizzle-kit generate — ПОСЛЕ правки src/db/schema.ts
npm start         # запуск бота (не делать, если работает launchd — будет ошибка 409)
scripts/launchd/restart.sh   # перезапуск бота после правки кода
```

`npm test` и `npm run typecheck` должны быть зелёными до того, как вы отдадите работу. `tsconfig.json`
включает `src`, `tests`, `scripts`, так что `typecheck` покрывает и тесты со скриптами.

## Инварианты (нарушение = сломанная архитектура)

1. **LLM — только через `@anthropic-ai/claude-agent-sdk`** (локальный Claude Code, `src/llm/claude-code.ts`).
   Никакого `@anthropic-ai/sdk`, никакого `ANTHROPIC_API_KEY`. Обращения идут через интерфейсы
   `WordEnricher` / `ExerciseTutor` из `src/llm/enricher.ts` и `src/llm/tutor.ts` — тесты подменяют их фейками.
2. **`src/services/` не импортирует `grammy`.** Сервисы — асинхронные функции, получающие `db` и `now`
   параметрами. Telegram-слой (`src/bot/`) тонкий и **не содержит SQL**.
3. **Запросы пишутся переносимо:** только `await db.select()/insert()/update()`, без sqlite-специфичных
   `.get()/.all()/.run()` и без `db.transaction`. Это сознательная плата за возможный переезд на Postgres.
4. **Импорты без расширений** (`moduleResolution: "Bundler"`, запуск через tsx).
5. **Язык интерфейса — всегда русский.** Меняется изучаемый язык (EN/KO), а не язык бота.
6. **Пользовательский и LLM-текст идёт через `esc()`**, сообщения отправляются с `parse_mode: "HTML"`.
7. **Не логировать текст личных сообщений.** В лог попадает только команда или факт (см. `src/bot/setup.ts`),
   токен вырезается через `redactLogs`.

## Изучаемый язык (EN/KO) — самое частое место ошибок

`src/lang.ts` держит язык текущей операции в `AsyncLocalStorage`. Вне контекста язык — английский,
поэтому старый код продолжает работать без правок.

- Ставит язык тот, кто знает комнату: middleware бота, API Mini App (`src/app/server.ts`), фоновые задачи.
- Читают — промпты, транскрипция, озвучка, подписи, через `currentLang()` / `langForms()` / `pickAccent()`.
- Очереди фильтруются по языку через `inCurrentLanguage()` (`src/services/language.ts`).
- **Английские строки и промпты должны оставаться байт-в-байт прежними** — это закреплено фикстурой
  `tests/fixtures/prompts-en.json` (`tests/prompts-lang.test.ts`). Если тест упал — вы сломали английский,
  а не «обновили ожидание».

## Тесты

- Стиль: `describe`/`it` из vitest, `tests/helpers.ts` даёт `testDb()`, `T0`, `at(ms)`, `makeUser()`.
  Время всегда контролируемое — `new Date()` в тестах не вызывать.
- **Телеграм-слой тестируется по-настоящему:** `tests/bot-harness.ts` поднимает реальные обработчики поверх
  фейкового Telegram API и собирает вызовы в `calls`. Новую кнопку или команду логичнее проверять там,
  а не описывать словами.
- Файлы называются по поведению, а не по модулю (`bugfixes-1018.test.ts`, `reverse-hint.test.ts`). Не
  переименовывайте их ради «порядка» — по именам ищут регрессии.

## База данных и эксплуатация

- Схема — `src/db/schema.ts` (18 таблиц). После её правки: `npm run db:generate`, получившуюся миграцию
  в `drizzle/` **коммитить**. Миграции применяет только сам бот при старте.
- Скрипты работают с живой базой в режиме `createDb(path, { migrate: false })` — схему они не меняют.
- База: `data/eng-bot.sqlite` (WAL). Бэкап — `scripts/backup.sh`, 14 последних в `data/backups/`.
- Бот живёт под launchd (`~/Library/LaunchAgents/com.engbot.*.plist`): бот, бэкап в 04:00, туннель ngrok.
  Логи — `data/logs/`. **Не запускайте `npm start` параллельно с launchd** — Telegram ответит 409.
- `data/` целиком в `.gitignore`. Ничего оттуда не коммитить.

## Баги

Пользователи сообщают о проблемах через `/bug` — они падают админу (`ADMIN_TELEGRAM_ID`) вместе с контекстом:
переписка и хвост логов.

```bash
npx tsx scripts/bugs.ts                                       # открытые
npx tsx scripts/bugs.ts --close=12 --note="Что сделано"       # исправлен, автору уходит сообщение
npx tsx scripts/bugs.ts --wontfix=12 --note="Почему так"
```

Закрывая баг, пишите `--note` по-русски и по делу: он уходит автору как объяснение. Починив баг,
упомяните его номер в сообщении коммита (как в `git log`).

## Что смотреть перед правкой

- `src/index.ts` — сборка всех зависимостей (`Deps`), единственное место, где всё соединяется.
- `src/bot/context.ts` — тип `Deps`: что доступно обработчику.
- `src/services/` — вся логика; `src/bot/handlers/` — по файлу на команду.
- `docs/architecture.md` — карта системы: путь апдейта, жизненный цикл карточки, язык операции, фоновые
  циклы. Читать, когда непонятно, **где** искать, а не **как** написан код.
- `docs/superpowers/` — **историческое планирование MVP (октябрь 2026), не описание текущего состояния.**
  Актуальная картина — код, тесты, `AGENTS.md` и `docs/architecture.md`.
