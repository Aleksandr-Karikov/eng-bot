description: Выбрать следующую готовую задачу из плана по влиянию, блокерам и стоимости. Используй для приоритизации и когда пользователь говорит «продолжай» без номера задачи.
---

Из `docs/INDEX.md` и `docs/PLAN.md` найди открытые задачи. Отсей закрытые и те, у которых не выполнена внутренняя или внешняя зависимость: в eng-bot это видно по блоку `➡️ **Сейчас:**`, где записано, чего ждёт задача. Не суди о блокере только по формулировке названия. История Git покажет, какие области недавно менялись и где контекст уже собран.

Для каждой кандидатуры оцени влияние на пользовательский путь и разблокировку других задач, объём затронутых слоёв (`src/services/` → граница → Mini App), нужны ли миграция и `npm run db:generate`, есть ли готовый похожий код, риск для приватности (в лог не должен попадать текст личных сообщений) и пересечение по файлам с текущей работой. Быстрая задача мала и самодостаточна; важная может быть дорогой, но разблокирует продукт.

Если просят определить приоритет, верни 2–3 самых влиятельных и, если уместно, 3–5 быстрых кандидатов: номер, место в плане, почему сейчас, объём, блокеры и риск. Если просят продолжить работу без номера, выбери одну готовую задачу и перейди к `repo-cycle`; не останавливайся на списке предложений. Если предложена новая идея, дай заготовку строки по формату из `docs/CONTRIBUTING.md`; не занимай номер и не меняй план без решения владельца.
