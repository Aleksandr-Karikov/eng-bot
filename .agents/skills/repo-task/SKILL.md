---
name: repo-task
description: Выполнить или закрыть продуктовую задачу по плану, приёмке и журналу приложения. Используй при изменении функции, поведения, API, прав или сборки; не для мелких правок и обслуживания шаблона.
---

1. Прочитай `AGENTS.md` (инварианты и гейт), `docs/architecture.md` (где искать), задачу из `docs/PLAN.md` и, если она закрыта, её журнал в `docs/journal/`. Начни с `npm run context E<номер>`: он печатает строку задачи и нужные документы. Прочитай строку до конца, включая блок `➡️ **Сейчас:**`. Закрытую или заблокированную задачу не начинай молча.
2. Найди зависимости, связанные журналы и похожий код. Сверь описание с текущим кодом: план мог устареть. Если задачи нет, добавь свободную строку `E<номер>` в `docs/PLAN.md` по формату из `docs/CONTRIBUTING.md` и выполни `npm run docs:index`. Правку самих документов и навыков в продуктовый план не записывай.
3. Убедись, что задача называет цель, пользовательский сценарий, данные и права, наблюдаемую приёмку и текущее состояние. Вопрос, который меняет поведение или контракт, разреши до реализации. Если вид нового экрана или крупного блока не задан однозначно, согласуй его по `repo-design` до написания UI. Краткий план раздели на связные срезы, после каждого из которых бот работает.
4. Сделай срез целиком: `src/services/` → граница (`src/bot/` или `src/app/`) → Mini App, если задача затрагивает оба, плюс тесты и документация. Соблюдай инварианты `AGENTS.md`: LLM только через `LlmBackend`, в `src/services/` нет `grammy`, запросы без sqlite-специфичных методов. Для существенного нового поведения нужен тест, который выявит откат. Время в тестах контролируемое — `new Date()` не вызывать.
5. Если затронут экран или текст в чате, проверь реальный сценарий по `repo-screen`. Перед завершением проверь дифф по `repo-review` и запусти гейт: `npm test && npm run typecheck`, при правке Mini App ещё `cd app && npm run build`. Красный результат из-за окружения назови отдельно; не выдавай его за проверенный код.
6. Закрой задачу лишь после сверки каждого пункта приёмки. Журнал `docs/journal/E<номер>.md` хранит первоначальную спеку, решения, фактические проверки и ограничения; закрытая строка плана сокращается до заголовка и ссылки на журнал. Затем `npm run docs:check`. Если часть не готова, оставь задачу открытой и запиши остаток в `➡️ **Сейчас:**`.
