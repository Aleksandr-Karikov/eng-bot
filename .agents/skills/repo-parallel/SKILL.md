---
name: repo-parallel
description: Спланировать независимые задачи для параллельной работы в отдельных Git worktree и безопасно свести результаты. Используй только по явному запросу на параллельную работу.
---

Из плана и кода собери след каждого блока: файлы, общие конфиги, миграции в `drizzle/`, реестры и внешние ресурсы. Параллельно запускай лишь блоки с непересекающимся кодом и раздельными рабочими каталогами. В eng-bot это ограничение жёсткое: вся логика живёт в одном процессе, а тесты слушают localhost, поэтому два прогона `npm test` одновременно мешают друг другу и падают на занятом порту. В отдельном worktree нужны свой `node_modules`, своё `data/` и своя копия `.env`; `data/` из общего каталога не переиспользуй, чтобы не менять живую базу. Общие документы (`docs/PLAN.md`, `docs/INDEX.md`) правятся после объединения блоков.

Держи один источник фактов по каждому блоку: задача, worktree, ветка, текущий коммит, гейт, ревью, блокер. Перед объединением обнови блок относительно целевой ветки, разреши конфликты, проверь, что финальный код совпадает с отревьюенным, и повтори затронутые проверки. Если обе ветки меняли `src/db/schema.ts`, порядок миграций в `drizzle/` восстанавливается на смерженном дереве, а не по одной из веток. Гейт до переноса не доказывает итог после переноса.

Объединяй по одному блоку. Не переписывай историю и не трогай чужие worktree без явной задачи. Автоматическое слияние, длительные циклы и внешнюю доску включай только через проектную обвязку, если она есть. Если в блоке нужен ответ человека, останови этот блок, сохрани его состояние и не выдавай соседний успех за его завершение.
