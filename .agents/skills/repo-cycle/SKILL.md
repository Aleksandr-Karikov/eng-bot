name: repo-cycle
description: Провести один связный блок задач от выбора до реализации, ревью и закрытия. Используй по просьбе «продолжай» без номера задачи или для автономной серии; не запускай бесконечный цикл.
---

Один вызов — один блок задач с общей причиной или пересекающейся областью. Сначала прочитай `AGENTS.md`, `docs/PLAN.md` и текущий Git-статус. Чужие незавершённые изменения не индексируй и не откатывай. Выбери готовый блок по `repo-choose-task` либо возьми заданные номера. При открытом продуктовом вопросе (например, менять ли экономику запаса в E1 или только объяснение), внешнем блокере или недоступной обязательной проверке оставь задачу открытой, запиши причину в `➡️ **Сейчас:**` и не объявляй её завершённой.

Для блока держи короткий список: контекст, реализация, проверка экрана при необходимости, гейт, независимое ревью, журнал и статус. Реализуй по `repo-task`; запусти `repo-verify`; экран проверь по `repo-screen`. Сверь дифф с приёмкой через `repo-review`. После исправлений по ревью проверь изменённые строки ещё раз, затем закрой задачу по `repo-close`. Не повторяй дорогой гейт на неизменном дереве и не запускай второй `npm test` параллельно с первым: тесты слушают localhost и мешают друг другу.

Коммит делай лишь когда запрос или проектные правила его разрешают. Перед коммитом убедись, что staged-файлы ровно те, которые прошли ревью, и что нет секретов. Публикацию и push отдельно не подразумевай. Закончи отчётом по одному блоку; следующий блок требует нового вызова, чтобы контекст и состояние оставались управляемыми.
