# Архитектура eng-bot

Карта того, что **не выводится из чтения одного места**: как проходит один апдейт целиком, как живёт
карточка, как устроен изучаемый язык и что работает в фоне. Схему БД смотрите в `src/db/schema.ts`,
перечень модулей — в структуре папок, правила правки — в `AGENTS.md`.

Дата: 2026-10-27. Проект молодой и меняется быстро (~9 коммитов в день), поэтому здесь описан только
каркас — то, что переживёт ближайшие правки. Детали реализации сознательно не пересказываются: они
устареют раньше, чем этот файл прочтут.

## Один процесс

Всё живёт в одном Node-процессе (`src/index.ts`): long polling Telegram, сервер Mini App, сервер приёма
слов из расширения и все фоновые циклы. Отдельных сервисов нет, координировать нечего.

```
src/index.ts — единственное место, где всё соединяется
   ├── createDb()            SQLite + миграции при старте
   ├── ProviderRouter        LLM (WordEnricher + ExerciseTutor): Claude Code или OpenRouter
   ├── Deps                  всё, что доступно обработчику (src/bot/context.ts)
   ├── startCaptureServer()  127.0.0.1:CAPTURE_PORT — слова из расширения
   ├── startAppServer()      127.0.0.1:APP_PORT — Mini App (/app/) и /ext
   ├── setupBot()            обработчики, middleware, меню команд
   ├── startReminderLoop()   фоновые рассылки, тик раз в минуту
   └── BackgroundPainter     фоновые картинки, тик раз в минуту
```

`Deps` — центральное понятие: это объект, который протаскивается в каждый обработчик и содержит
`db`, LLM-интерфейсы, `now`, `random`, notifier и хранилища состояний. Тесты собирают такой же `Deps`
с фейками (`tests/bot-harness.ts`), поэтому всё внешнее — LLM, озвучка, распознавание, картинки —
спрятано за интерфейсами и подменяется.

Обратите внимание: `englishSpeech` (Kokoro) живёт **вне** `Deps`, потому что это долгоживущий
Python-процесс, который надо закрыть при выходе. Остальное создаётся и передаётся через `Deps`.

## Один апдейт целиком

```
Telegram → grammY
  → autoRetry           429 «подожди N секунд» пережидаем, до 30 с (иначе шаг рвётся на полпути)
  → retryNetworkErrors  сетевые сбои
  → transcript          запись «что бот сказал и что нажал человек» — для /bug
  → ignoreHarmlessErrors
  → slowApiCallLogger   > 2 с — в лог
  → userMiddleware      регистрация, can_dm, комната группы, и вот здесь — язык
  → обработчик          src/bot/handlers/<команда>.ts
```

`userMiddleware` ставит язык операции через `withLang()`. Дальше он доступен откуда угодно через
`currentLang()` — именно поэтому язык не протаскивается параметром через сотни функций.

**Обработчики тонкие.** Логика — в `src/services/`, чистыми асинхронными функциями, принимающими
`db` и `now`. Это не стилистика: благодаря этому 530 тестов работают без Telegram и без сети.

## Жизненный цикл карточки

Слово добавляется один раз, а карточек у него **по одной на каждого участника комнаты** — со своим
графиком FSRS. У слова и карточки разные владельцы: слово принадлежит комнате, карточка — человеку.

```
/add слова → word (комната)  → cards у всех участников (State.New)
                             → «знаешь?» остальным: учу / уже знаю / не для меня
                                          └→ triage: решение, чтобы слово не возвращалось
/learn → очередь due → ступень выбирается по карточке → ответ → FSRS (again/hard/good/easy)
```

**Ступень упражнения выбирается по состоянию карточки, а не по её стабильности** — это важно, потому
что в спеке MVP (июльский замысел) было иначе. Смотрите `pickStage()` в `src/services/exercises.ts`:
новая карточка всегда идёт на «первое знакомство», дальше ступень выбирается случайно из доступных,
где доступность зависит от включённых режимов, наличия предложений с пропуском и числа повторов.
Ошибка снижает стабильность → слово само спускается на более простую ступень.

Ступени `sentence` и `listen` требуют ответа сообщением, поэтому ожидаемый ответ живёт в `ExerciseStore`
(`src/bot/exercises.ts`) — в памяти ради скорости, но **с записью в `pending_exercises`** и загрузкой
обратно при старте (`load()`). Перезапуск бота незавершённое упражнение не теряет; записи в БД идут
строго по очереди, чтобы «удалить» не обогнало «сохранить».

## Изучаемый язык

Язык — свойство **комнаты**, не пользователя: в одной комнате учат английский, в другой корейский,
и человек ходит между ними через `/lang`.

```
room.language ──► withLang() ──► AsyncLocalStorage ──► currentLang()
                   ▲                                        │
     middleware бота, API Mini App, фоновые задачи           ├─► промпты (src/llm/)
                                                            ├─► транскрипция / романизация
                                                            ├─► озвучка, голос
                                                            └─► подписи в текстах
```

Вне контекста язык — английский. Это не мелочь, а причина, по которой корейский удалось добавить,
не переписывая обработчики: старый код продолжает работать как раньше.

**Порядок очередей фильтруется по языку** (`inCurrentLanguage()`), иначе в корейской комнате
показывались бы английские слова из других комнат того же человека.

**Главная ловушка:** английские промпты обязаны оставаться байт-в-байт прежними — это закреплено
фикстурой `tests/fixtures/prompts-en.json`. Если `tests/prompts-lang.test.ts` упал, вы сломали
английский, а не «обновили ожидание».

## Провайдер LLM

Провайдер — это **только транспорт**: один запрос «промпт → текст». Всё остальное (какой промпт собрать,
как разобрать ответ, какая модель для чего) одинаково и живёт в `src/llm/enricher.ts` и `src/llm/tutor.ts`.

```
WordEnricher + ExerciseTutor (19 методов)   src/llm/enricher.ts, tutor.ts
        │  промпт и разбор ответа — общие для всех провайдеров
        ▼
  ProviderRouter                              src/llm/provider.ts
        ├── ClaudeCodeEnricher ─► ClaudeCodeBackend  локальный Claude Code (без ключа)
        └── ClaudeCodeEnricher ─► OpenRouterBackend  OpenRouter (ключ + имя модели)
```

Роутер держит по экземпляру на провайдера, и переключение — это замена ссылки: **перезапуск не нужен**,
начатые запросы дорабатывают там, где начались. Поэтому `/llm` в боте (для админа) и
`npx tsx scripts/llm.ts` переключают модель на живой системе.

Два следствия, которые чаще всего удивляют:

- **Имена моделей не переводимы друг в друга.** `haiku` — алиас Claude Code, `anthropic/claude-haiku-5.5` —
  имя у OpenRouter; у каждого провайдера свои переменные (`ENRICH_MODEL` / `OPENROUTER_MODEL`, см. `src/llm/models.ts`).
- **Модель выбирается внутри метода, а не в роутере** (`this.opts.model`, `this.checker`, `mnemonicModel`),
  поэтому наборы моделей принадлежат экземпляру, а не запросу.

Выбор провайдера переживает перезапуск: он лежит в файле `data/llm-provider` (`src/llm/provider-store.ts`),
потому что бот не переписывает `.env` — там ключи. Порядок при старте: файл → `LLM_PROVIDER` → Claude Code.

## Что работает в фоне

Два цикла с тиком раз в минуту, оба идемпотентны — при простое мака догоняют, но не дублируют.

**`startReminderLoop`** (`src/reminder-loop.ts`) — шесть рассылок в одном тике, по порядку: личные
напоминания, «слова появились», дайджесты, достигнутые цели, недельные отчёты, слово дня в группы.
Флаг `running` не даёт тикам наложиться. Факт отправки пишется в БД (`markReminded`, `markDueNotice`),
поэтому повторный тик ничего не отправит второй раз.

**`BackgroundPainter`** (`src/images/painter.ts`) — рисует картинки заранее, пока очередь пуста
и мак на зарядке. Выключен без `IMAGES_ENABLED=1` и без `IMAGES_BACKGROUND`.

Обе рассылки идут через `Notifier`, который знает про `can_dm`: если человек заблокировал бота,
это не роняет весь тик.

## Три входа в одну систему

| Вход | Кто пользователь | Где |
|---|---|---|
| Бот | Telegram-апдейт | `src/bot/`, `userMiddleware` |
| Mini App | подписанные `initData` | `src/app/server.ts`, `/api/*` |
| Расширение | личный `captureKey` | `src/capture/server.ts`, только 127.0.0.1 |

Все три в итоге вызывают одни и те же функции из `src/services/` — очередь, FSRS и прогресс общие.
Поэтому правка в сервисе видна сразу во всех трёх, а новый эндпоинт Mini App обязан сам поставить
язык через `withLang()`, иначе он молча ответит по-английски.

## Ошибочные представления, которые стоит снять

- **`docs/superpowers/`** — замысел MVP от 15–17 октября, а не текущее состояние. Расхождения
  (например, выбор ступени) объясняются тем, что систему изменили после написания спеки.
- **«Проект про английский»** — в коде два языка с самого начала ветки `feature/korean`.
- **Карточка ≠ слово.** Прогресс, ступени и FSRS — у карточки; перевод, примеры и мнемоника — у слова.
