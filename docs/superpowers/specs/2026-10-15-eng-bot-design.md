# eng-bot — дизайн MVP

Дата: 2026-10-15

## Цель

Telegram-бот для совместного заучивания английских слов с друзьями. Участники общей комнаты
добавляют слова, остальные получают уведомление «знаешь?», а каждый учит слова в личке по
алгоритму интервальных повторений (FSRS).

**Для кого:** автор и несколько друзей (до ~10 человек). Публичный запуск не планируется,
но архитектура не должна ему мешать.

**Критерии успеха MVP:**
- можно создать комнату, пригласить друзей и (опционально) привязать Telegram-группу;
- добавленное слово дополняется LLM (перевод, объяснение, пример), подтверждается автором
  и рассылается участникам;
- каждый участник повторяет слова через `/learn`, интервалы считает FSRS;
- раз в день приходит напоминание, если есть слова к повторению;
- `/stats` показывает личный прогресс и таблицу комнаты.

## Решения и ограничения

| Решение | Выбор |
|---|---|
| Язык | TypeScript (Node.js) |
| Telegram | grammY, long polling |
| БД | SQLite через Drizzle ORM; переход на Postgres = смена драйвера и миграций |
| SRS | ts-fsrs |
| LLM | Claude Code через Claude Agent SDK (`@anthropic-ai/claude-agent-sdk`, модель `haiku`), за интерфейсом `WordEnricher`. Прямых запросов к Anthropic API нет, `ANTHROPIC_API_KEY` не используется — работает локальная авторизация Claude Code |
| Тесты | Vitest, SQLite in-memory, фейковый LLM |
| Хостинг | сначала локально на маке (`caffeinate`/pm2), позже Docker на VPS |
| Языки | фиксированная пара: английский → русский |
| Лимиты | без лимита новых слов в день |

**Вне MVP:** еженедельный дайджест, мотивирующие сообщения о прогрессе друзей, картинки-ассоциации,
режим теста с вариантами, ввод перевода текстом, другие языковые пары, лимит новых слов.

## Модель данных

- **users**: `id`, `telegram_id` (unique), `first_name`, `username`, `reminder_time` (по умолчанию `20:00`),
  `timezone` (по умолчанию `Europe/Moscow`), `current_room_id` (nullable),
  `last_reminder_date` (nullable, локальная дата последнего напоминания),
  `can_dm` (bool, false пока пользователь не нажал Start или если бот заблокирован), `created_at`.
- **rooms**: `id`, `name`, `invite_code` (unique), `telegram_chat_id` (nullable, unique — привязанная группа),
  `created_by`, `created_at`.
- **room_members**: `room_id`, `user_id`, `joined_at`; PK (`room_id`, `user_id`).
- **words**: `id`, `room_id`, `added_by`, `term`, `term_normalized` (lowercase, trim),
  `translation`, `explanation`, `example`, `created_at`; unique (`room_id`, `term_normalized`).
- **cards**: `id`, `user_id`, `word_id`, FSRS-поля (`due`, `stability`, `difficulty`, `elapsed_days`,
  `scheduled_days`, `reps`, `lapses`, `state`, `last_review`); unique (`user_id`, `word_id`).
- **review_logs**: `id`, `user_id`, `card_id`, `rating`, `reviewed_at`.

Слово общее для комнаты, карточка — личный прогресс участника по слову.

## Жизненный цикл карточки

- При сохранении слова карточка (`state = New`, `due = now`) создаётся для каждого участника комнаты,
  включая автора.
- Участникам, кроме автора, с `can_dm = true` приходит в личку «{автор} добавил *{term}* — знаешь?»
  с кнопками «Знаю» / «Не знаю».
  - «Знаю» → `review(card, Easy)`: FSRS отодвигает карточку далеко вперёд.
  - «Не знаю» или нет ответа → карточка остаётся New и придёт в ближайшем `/learn`.
  - Повторное нажатие на уже обработанное уведомление игнорируется («уже учтено»).
- При вступлении в комнату новичок получает New-карточки на все существующие слова, без уведомлений.
- В `/learn` у New-карточки есть дополнительная кнопка «✅ Уже знаю» (= Easy).

Маппинг кнопок на FSRS: 😵 Забыл → Again, 😐 С трудом → Hard, 😎 Помню → Good, ✅ Уже знаю / Знаю → Easy.

## Структура модулей

```
src/
  bot/        — grammY: команды, callback-кнопки, тексты. Только интерфейс, без логики.
  services/   — rooms, words, review, stats, reminders. Вся бизнес-логика.
  srs/        — обёртка над ts-fsrs: review(card, rating, now) → { card, log }.
  llm/        — интерфейс WordEnricher { enrich(term) → { translation, explanation, example } }
                + реализация через Claude Agent SDK (локальный Claude Code).
  db/         — схема Drizzle, миграции, создание подключения.
  notifier/   — отправка в группу/личку, обработка 403 (выставляет can_dm = false).
  config.ts   — переменные окружения (BOT_TOKEN, DB_PATH, ENRICH_MODEL, ENRICH_TIMEOUT_MS).
  index.ts    — сборка зависимостей и запуск.
```

Сервисы получают зависимости (db, enricher, notifier, clock) через параметры, поэтому
тестируются без Telegram и сети.

## Потоки

### Комнаты
- `/start` — регистрирует пользователя, выставляет `can_dm = true`. С payload `join_<code>` —
  вступление в комнату и установка её текущей.
- `/room` — показывает текущую комнату и кнопки: создать новую, получить ссылку-приглашение
  (`t.me/<bot>?start=join_<code>`), переключить текущую.
- `/link` в группе — привязывает группу к текущей комнате вызвавшего (если группа ещё не привязана).
  Если у вызвавшего нет комнаты — создаётся новая с названием группы.
- Любое взаимодействие пользователя с ботом в привязанной группе добавляет его в комнату.
  Если `can_dm = false`, бот один раз отвечает в группе со ссылкой на запуск бота.

### Добавление слова
1. В личке: `/add <term>` или просто текст. В группе: только `/add <term>`.
   Формат `term — перевод` сохраняет перевод пользователя, LLM дополняет объяснение и пример.
2. Если у пользователя нет текущей комнаты — бот предлагает создать её.
3. Если `term_normalized` уже есть в комнате — сообщение «уже есть», конец.
4. `enricher.enrich(term)` → черновик с кнопками ✅ Ок / ✏️ Исправить / ❌ Отмена.
   Черновик хранится в памяти процесса (DraftStore, один активный черновик на пользователя).
5. ✏️ — бот просит прислать перевод ответом на своё сообщение (force_reply — так ответ виден боту
   и в группах с privacy mode); этот ответ заменяет перевод.
6. ✅ — сохранение слова, создание карточек, рассылка: объявление в привязанную группу
   (если есть) + «знаешь?» в личку участникам.

### Повторение (`/learn`)
1. Очередь: карточки пользователя из всех его комнат с `due <= now`; сначала не-New по `due`,
   затем New по дате создания.
2. Одно сообщение редактируется на месте: слово + «Показать» → перевод, объяснение, пример
   + кнопки оценки.
3. Ответ → `srs.review` → обновление карточки, запись `review_logs` → следующая карточка.
4. Очередь пуста → «Готово! N слов. Следующее повторение: <когда>».
5. Нажатие на кнопку устаревшей карточки (уже оценённой) игнорируется.

### Напоминания
- Таймер раз в минуту: для пользователей с `can_dm = true`, у которых локальное время ≥ `reminder_time`,
  `last_reminder_date` ≠ сегодня (локально) и есть карточки с `due <= now` — отправить
  «🔔 N слов ждут повторения» с кнопкой «Начать» и записать `last_reminder_date`.
- Если к повторению ничего нет — `last_reminder_date` всё равно выставляется, сообщение не шлётся.
- Та же проверка отправляет пропущенное напоминание после того, как мак проснулся.
- `/settings` — смена `reminder_time` (кнопки с популярными часами + ввод `HH:MM`).

### Статистика (`/stats`)
- Личное: всего карточек, выучено (state = Review и stability ≥ 21 дня), в изучении,
  новых, повторений за 7 дней, серия дней подряд с хотя бы одним ответом (по `review_logs`,
  в часовом поясе пользователя).
- Комната (текущая): таблица участников — выучено и повторений за 7 дней, отсортировано по повторениям.

## Обработка ошибок

- LLM недоступен / таймаут (30 с — Claude Code стартует несколько секунд) / невалидный ответ → бот просит ввести перевод вручную,
  объяснение и пример остаются пустыми.
- 403 при отправке в личку → `can_dm = false`, без падения. 403/400 в группе → лог, без падения.
- Необработанные ошибки в хендлерах ловит `bot.catch`: лог + «Что-то пошло не так» пользователю.
- LLM-ответ запрашивается в JSON и валидируется (zod).

## Тестирование

- Vitest, unit-тесты на `services/` и `srs/` с SQLite in-memory, фейковыми enricher/notifier и
  контролируемыми часами.
- Ключевые сценарии: создание слова → карточки у всех участников; «Знаю» → due далеко в будущем;
  очередь `/learn` в правильном порядке; дубликат слова; вступление в комнату создаёт карточки;
  напоминание отправляется ровно раз в день и догоняет после простоя; подсчёт серии дней.
- Telegram-слой проверяется вручную на тестовом боте.

## Дополнение (2026-10-17): режимы тренажёра

**Лесенка.** У слова одна карточка и один график FSRS. Упражнение выбирается по стабильности карточки:

| Стабильность | Ступень |
|---|---|
| New или < 3 дней | 1 — EN → RU: слово + транскрипция, ответ под спойлером, кнопки «Забыл / Помню» |
| 3–14 дней | 2 — RU → EN: перевод, английское (+ транскрипция, пример) под спойлером, те же кнопки |
| > 14 дней | 3 — вставь по смыслу: предложение с `___` + русский перевод фразы, ответ сообщением |

- Выключенные режимы пропускаются: берётся ближайшая включённая ступень ниже целевой, иначе ближайшая выше.
- Ошибка снижает стабильность → слово само спускается на ступень проще.

**Вставь по смыслу.**
- Ответ нормализуется (регистр, пробелы, конечная пунктуация, кривые апострофы). Совпал с формой в пропуске или с самим словом → «✅ Верно» = Good.
- Иначе проверяет Claude: подходит (синоним, допустимая форма, опечатка) → Good с пояснением; не подходит → Again, правильный ответ, объяснение и совет.
- Claude не ответил → показываем правильный ответ и кнопки «Забыл / Помню».
- «🤷 Не знаю» → Again, показываем ответ.
- После разбора сразу приходит следующая карточка.
- Ожидаемый ответ хранится в памяти (одно упражнение на пользователя). Текст в личке, пока ждём ответ, не уходит в /add.

**Предложения с пропуском.**
- Таблица `cloze_sentences` (word_id, sentence, answer, translation), 3 на слово, общие для комнаты, показываются по очереди (`reps % n`).
- Генерируются в фоне, когда карточка дорастает до ступени 3 (после ответа или при показе). Пока предложений нет — ступень 2.
- Удаляются вместе со словом; при /edit удаляются и пересоздаются позже.

**Настройки.** `users.mode_en_ru`, `mode_ru_en`, `mode_cloze` (по умолчанию true). Переключатели в /settings; последний включённый выключить нельзя.

**LLM.** Отдельный интерфейс `ExerciseTutor { cloze(term, translation); judge(...) }` в той же реализации через Claude Agent SDK.
