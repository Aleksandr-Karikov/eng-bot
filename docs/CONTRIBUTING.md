# Путь задачи

Как требование превращается в строку плана, код, журнал и закрытую задачу. Правила самого кода —
в [AGENTS.md](../AGENTS.md); карта системы — в [architecture.md](architecture.md).

## 1. План и контекст

Для функции, изменения поведения, API, прав или сборки нужна задача. Если её нет, добавь следующую
свободную строку `E<номер>` в [PLAN.md](PLAN.md): цель и сценарий, данные и права, наблюдаемая
приёмка и текущее состояние. Неизвестное помечай вопросом; если ответ меняет поведение или контракт,
получи его до правки. Опечатка, комментарий и другая мелкая правка без изменения поведения обходится
без строки плана и журнала.

```bash
npm run docs:index        # обновить индекс после правки плана
npm run context E1        # строка задачи и ссылки на нужные документы
npm run docs:check        # проверить план, индекс и журналы
```

## 2. Правка

Изучи код и существующие тесты. Делай связанное изменение целиком: `src/services/` → граница
(`src/bot/` или `src/app/`) → Mini App, если задача затрагивает оба. Соблюдай инварианты из
`AGENTS.md`; первый из них — LLM только через `LlmBackend`, второй — в `src/services/` нет `grammy`.

Для нового поведения нужен тест, который падает при возврате старого. Время в тестах контролируемое
(`T0`, `at(ms)`), `new Date()` не вызывать. Телеграм-слой проверяется через `tests/bot-harness.ts`, а не
описанием словами.

Если задача задевает экран Mini App, перед завершением запусти его и проверь сценарий руками —
включая загрузку, пустое состояние и отказ. Скриншот упавшего теста не считается проверкой экрана.

## 3. Завершение

Для задачи из плана создай `docs/journal/E<номер>.md` с разделами «Спека», «Что сделано»,
«Решения и ограничения», «Проверено». Укажи реальные команды и результат; непроверенное не записывай
как проверенное. Закрытую строку в плане сократи до заголовка и ссылки на журнал.

```bash
npm test && npm run typecheck            # основной гейт, CI гоняет то же
cd app && npm run build                  # если менялся Mini App
npm run docs:index && npm run docs:check # если менялся план
```

Одна задача или связанный блок — одна ветка и один коммит. Сообщение коммита описывает результат
и проверки, а не список файлов. Не коммить секреты и содержимое `data/`.

## Блокеры

Если задачу нельзя закрыть — нет ответа владельца, мешает контракт или недоступна обязательная
проверка — оставь её открытой и запиши остаток в `➡️ **Сейчас:**`. Значок `[x]` означает «приёмка
выполнена», а не «работа остановлена».
