## Что чинить первым

### 1. IDOR: чужое слово можно присвоить и прочитать

`[P0]` `src/services/triage.ts:52` + `src/app/api.ts:335`

`POST /api/triage {action:"drop", undo:true, wordId:N}` вызывает `restoreCard(userId, wordId)`
без проверки, что слово принадлежит комнате этого человека. Ветка `drop` не сверяет `cardId`
с `wordId` и не зовёт `isMember`.

Проба (пользователь вне комнаты):

```
mallory member of alice room? false
ok= true  mallory sees: [ [ 'secretword', 'секретный перевод' ] ]
```

Перебор `wordId` выгружает приватные словари всех комнат. Каждое внедрённое слово дополнительно
запускает фоновую подготовку (сочетания, пропуски, грамматика) — то есть ещё и платные вызовы модели.

**Исправление:** брать слово из карточки и проверять `isMember`; `wordId` из тела не доверять.
Цена: S.

### 2. Лимит на слова обходится без гонки и без условий

`[P0]` `src/bot/handlers/batch.ts:117`

`saveItems` сохраняет слова по `batch.left` — снимку остатка **на момент показа списка** — и вызывает
`spendWordQuota`, результат которой игнорируется. Если остаток израсходован другим путём (Mini App,
расширение, второй человек в комнате), слова всё равно сохраняются.

Проба (остаток израсходован до «✅ Добавить»):

```
left at offer: 50 → left now: 0
saved=50  used=50  limit=50
```

Это единственная находка, где лимит обходится **полностью и без параллельности**. Каждое слово —
платные `enrich` + `mnemonics`, то есть обход прямо конвертируется в расход.

**Исправление:** проверять остаток перед каждым `saveWord` и останавливаться, а отказ доводить
до человека (остальные слова — «добавим завтра»). Цена: S.

### 3. Общий потолок расхода картинок не держит параллельные запросы

`[P0]` `src/services/limits.ts:415` (`checkAndSpend`)

Та же гонка, что у `checkAndCount`, но на **общий** потолок, который существует ради денег.

Проба (потолок 200):

```
budget limit=200  allowed=300  used=300
```

Перерасход 100 картинок за эпизод — по оценке из комментария в файле (200 картинок ≈ $6.7/день)
это около $3.35 сверх потолка. Путь реальный: `drawAndSend` вызывается из `background()`
(`bot/handlers/mnemonic.ts`), то есть обработчики не ждут друг друга, а Mini App приходит отдельными
HTTP-запросами.

**Исправление:** тот же приём, что уже применён для кошелька — условный инкремент с проверкой
`count < limit` в самом `UPDATE`/`INSERT ... SELECT`, а не «прочитать, потом записать». Цена: S.

### 4. Токен бота может попасть в `/bug` (мина, не текущая утечка)

`[P1]` `src/log-buffer.ts:5` + `src/index.ts:61-66`

`redactLogs` ставится на `console` первым, `captureRecentLogs()` — вторым, поэтому буфер записывает
**сырые** аргументы, минуя редакцию. Комментарий в файле («Ставить после `redactLogs` (без токена)»)
неверен: проверка даёт `contains raw token: true`.

Но текущие логгеры секрет не печатают: grammY при `sensitiveLogs: false` (значение по умолчанию,
`node_modules/grammy/out/core/client.js:83`; в `src/index.ts` флаг не выставлен) не выводит URL
с токеном, а `fetch` при сетевом сбое даёт `TypeError: fetch failed` без адреса. То есть это мина:
она срабатывает, как только в `console.warn`/`error` попадёт строка с URL. Собирать такой URL уже
умеют два места — `src/bot/files.ts:37` и `src/app/api.ts:307`.

**Исправление:** `captureRecentLogs()` до `redactLogs`, либо передавать буферу функцию-редактор,
а не полагаться на порядок вызовов. Тест: «секрет не появляется в `recentLogs()`». Цена: S.

### 5. Вечный цикл в `/learnnew` останавливает бота

`[P1]` `src/bot/handlers/learn-widget.ts:63`

```ts
while (size() > WIDGET_DATA_LIMIT) data.a = data.a.slice(0, -10);
```

Режется только перевод. Если `term` сам больше 1024 байт, `size()` не падает никогда:

```
term=200 chars:  returned normally
term=1100 chars: INFINITE LOOP: 200001 iterations, a became ""
```

Апдейты обрабатываются по одному, поэтому встаёт весь бот до перезапуска. Приоритет P1, а не P0,
по одной причине: `cardData` вызывается только из `/learnnew` — команды для админа в личке, пробы
виджетов Bot API (`src/bot/setup.ts:127`, `learn-widget.ts:70-72`).

Важный маршрут, который делает это чужим багом: слово в общей комнате создаёт карточки **всем**
участникам (`services/words.ts:106`). Значит обычный участник может положить слово длиннее 1024 байт
в общую комнату, а зависнет бот у админа, когда тот откроет `/learnnew`. Обычный `/learn` не страдает
(карточка с таким словом — 1190 символов, меньше 4096).

**Исправление:** ограничить `term` при сохранении, резать все поля, заменить `while` на конечный
цикл с усечением остатка. Цена: S.

## Кажущиеся кандидаты, которые лучше оставить

- **`src/grammar/*` (22 файла)** — это данные. Дробление ухудшит навигацию и сломает
  `scripts/check-grammar-file.ts`.
- **`src/bot/texts.ts`, `src/llm/tutor.ts`, `src/db/schema.ts`** — высокая связность по смыслу;
  разнос по файлам усложнит поиск пар «промпт ↔ парсер».
- **`src/services/language.ts` без прямых тестов** — фильтрация очередей покрыта косвенно; отдельный
  тест дублировал бы `korean.test.ts`.
- **`practiceQueue` без `userId` в фильтре логов** — было заявлено как доменный баг; проверка
  показала, что фильтр идёт по `cardId`, чужие ответы не влияют. Остаётся только производительность.
- **Отсутствие `db.transaction`** — принятое решение. Атомарность достигается условными `update`
  и `onConflict`; это применено правильно в кошельке и бою.
- **`checkText` / `/users` / список тем** — уже имеют потолок под 4096, трогать не нужно.

- Повторная доставка апдейта после падения посреди обработчика: `update_id` в проекте не
  используется нигде. Оценка карточки защищена `expectedReps`, но `duelPoints` и `saveBug` — нет
  (гипотеза).
- Правила геймификации целиком: разбор по этому направлению не был завершён. Проверено точечно —
  маппинг оценок FSRS корректен (`srs.ts:15-18`), `retentionFor` устойчив к мусору, экономика монет

## Что признано здоровым

- `esc()` покрывает пользовательский и LLM-текст в текстовых сборщиках; обратного случая
  (`esc()` без `parse_mode`) не найдено.
- `answerCallbackQuery` вызывается во всех обработчиках кнопок; есть catch-all для устаревших.
- `callback_data` компактен (замер: до 20 байт при лимите 64); `inline`-id режется с учётом байт.
- `checkText` держит потолок 3800 и умеет сокращаться; `/users` пакует по 3800.
- Все `spawn`/`execFile` с таймаутом, временные каталоги удаляются в `finally`.
- Ни одного `db.transaction`, `.get()`, `.all()`, `.run()` в `src`.
- `src/services/` не импортирует `grammy` (кроме двух мест с `import type` в `src/app/`).
- zod применяется систематически в разборе ответов модели; есть `safeParse` с отбрасыванием
  битых пунктов; есть тесты на мусор от модели.
- Идемпотентность **денежных операций кошелька и боя**: `walletSnapshot` + условный `update`,
  уникальные индексы `combat_spends`. Гонка осталась в счётчиках квот и бюджета (см. выше) —
  это разные механизмы.
- Время в тестах контролируемое; таймзоны и переход на летнее время покрыты.
- Один вход в модель: единственный импорт SDK в `src/llm/claude-code.ts`.
- grammY настроен безопасно: `sensitiveLogs` не включён, тело ответа API в текст ошибки не попадает.

## Как ревью проверялось

Первую версию отчёта разобрал независимый критик. Он перепроверил находки и нашёл в них реальные
ошибки — отчёт исправлен по его замечаниям:

- **Два P0 понижены до P1.** Про токен: механизм подтверждён, но grammY не печатает URL с токеном,
  поэтому это мина, а не текущая утечка. Про виджет: цикл подтверждён, но команда админская,
  а ценность — в межпользовательском маршруте (через общую комнату). Завышать было неверно.
- **`USE TEMP B-TREE` привязан не туда.** План принадлежит `nextReviewAt` (экран «Готово»),
  а не очереди `/learn`: `dueItems` сортирует в JS, её план индекса не требует.
- **Замеры пересчитаны на реальном масштабе.** Комната с максимумом слов в прод-копии — 365,
  а не 2000: `word-of-day` там 3.2 мс, а не 160 мс. Разница `Intl` честно ×15–24, не ×25.
- **Оценка `max_tokens` уточнена:** 49–74 пункта (зависит от длины `context`), и дефект только
  у OpenRouter.
- **Пропущена была гонка на общий потолок** (`checkAndSpend`) — она в отчёте появилась и стала P0:
  потолок 200 пропускает 300, это деньги.
- Пропущенные зоны добавлены: `deploy.py` без отката, `extension/` и `app/src` вне проверок.
