# E35 — Переименовать `src/services/source.ts` в `start-payload.ts`

## Спека

Модуль разбирает payload команды `/start`, но имя `source` читается как «источник» вообще — рядом
живут `sources.ts` (скрипт источников привлечения) и `words.source`, и по имени не понять, о чём файл.

Приёмка: файл переименован, импорты обновлены, `npm run typecheck` и тесты зелёные; поведение не
меняется.

## Что сделано

- `src/services/source.ts` → `src/services/start-payload.ts` (через `git mv`, чтобы история файла
  сохранилась).
- `tests/source.test.ts` → `tests/start-payload.test.ts` — файл теста назван по модулю, который
  проверяет.
- Импорт обновлён в одном месте `src`: `src/bot/handlers/rooms.ts`.

## Решения и причины

- **`start-payload`, а не `payload` или `start`.** В имени должны читаться и «что разбираем»
  (payload), и «откуда» (`/start`). `source` не читался никак.
- **Тест переименован вместе с модулем.** В проекте принято называть тесты по поведению, но здесь
  файл проверяет ровно один модуль целиком, и старое имя стало бы ложью: `source.test.ts` рядом с
  `sources.test.ts`, которого нет, но есть `scripts/sources.ts`.
- **`git mv`, а не удаление и создание.** Иначе история правок файла потерялась бы.

## Проверки

```
npx vitest run tests/start-payload.test.ts  → 12 tests passed
npx tsc --noEmit                            → чисто
grep "services/source\"" src/ tests/ scripts/ → пусто
```

## Известные ограничения

- **`users.source` и `services/sources.ts` не тронуты.** Первое — колонка в базе (значение «откуда
  пришёл»), второе — сводка по этим значениям. Они называются верно; путаница была только с третьим
  файлом, который их не касается.
- **Поведение не менялось**, поэтому отдельного теста на «ничего не сломалось» нет — есть зелёные
  существующие 12 тестов модуля.
