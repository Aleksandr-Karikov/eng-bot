# E5 — «Уже знаю» даёт максимальный базовый урон без проверки

## Спека

`markKnown` отправляет `easy` для карточки в состоянии `New` с `reps = 0`, то есть 3 HP за нажатие —
максимум базовой таблицы без усилия. Ограничение новыми словами не давало эксплойта, но перекашивало
вклад участников: человек получал больше урона за свайп, чем другой за «Помню» после раздумий.

Приёмка: решение либо оставляет поведение и объясняет его в интерфейсе, либо требует проверки; тест
фиксирует выбранное правило.

Решение владельца: урон в общую цель не давать — свайп «уже знаю» это знакомство, а не работа.
`markKnown` продолжает закрывать карточку, но вес ответа для стадии `know` равен 0.

## Что сделано

- `src/services/goals.ts` — добавлена константа `KNOW_STAGE = "know"`; в начале `answerWeight` стоит
  `if (stage === KNOW_STAGE) return 0`. Проверка идёт до расчёта базы, поэтому усиление, реликвии, серия
  и бонус Дракона на этот ответ не влияют вообще — ноль есть ноль.
- `src/services/review.ts` — `markKnown` использует константу вместо строкового литерала `"know"`.
  Логика не изменилась: карточка по-прежнему получает `easy` в FSRS и уходит вперёд по расписанию.
- `tests/review.test.ts` — два теста: «не двигает цель комнаты, но убирает карточку из очереди»
  и ««Помню» на той же карточке цель двигает» (контроль, что обнуление не задело остальные оценки).
- `docs/architecture.md` — в раздел про вес ответа добавлен абзац про «уже знаю» и причину.

## Решения и причины

- **Урон 0, а не «меньше урона».** Приёмка разрешала либо убрать урон, либо объяснить его в интерфейсе.
  Объяснять пришлось бы правило, которого нет: свайп не задаёт ни одного вопроса, значит и измерять
  нечего. Ноль — единственное правило, которое не требует оправданий в тексте.
- **Карточка всё равно закрывается как `easy`.** Это осознанно и осталось: человек сообщает, что слово
  ему знакомо, и мучить его повторениями незачем. Изменился только вклад в общую цель, а не расписание.
- **Константа вместо литерала.** Строка `"know"` встречалась в двух местах (`markKnown` и новые тесты);
  общая константа не даёт им разойтись, если стадию когда-нибудь переименуют.
- **Замер по копии прод-базы:** 48 ответов со стадией `know` из 6635 (0.7%). То есть правка не обнуляет
  заметную часть чужой истории, а закрывает лазейку на будущее.

## Проверки

```
npx vitest run tests/review.test.ts  → 9 tests passed
npx vitest run                        → 119 files, 836 tests passed
npx tsc --noEmit                      → чисто
```

Тест проверен на старом коде (`git stash push src/services/goals.ts src/services/review.ts`) и падает
по существу: `expected 3 to be +0` — ровно три HP за нажатие.

## Известные ограничения

- **Историю не пересчитывал.** В уже записанных `review_logs` у 48 ответов со стадией `know` урон
  зафиксирован прежним значением. Прошедшие недели остаются как были — это осознанно, как и в E2.
- **`answerWeight` вызывается без стадии в трёх местах** (`roomReviews`, `trophies`, `personalDamage`) —
  там это запасной путь для старых записей без `damage_deci`. У таких строк урон остаётся прежним,
  потому что `stage` у них сохранён и равен `"know"` только если он был записан; пересчёта нет.
- **В интерфейсе ничего не сказано про ноль.** Человек, нажавший «Знаю», не увидит «+0 HP» — урона в
  этом сообщении не показывается вовсе, так что и объяснять нечего.
- **Подсказка в Mini App не менялась.** Свайп «Знаю» там подписан так же, как раньше; отдельной пометки
  «в цель не идёт» нет.
