# E39 — В вопросе на сочетания не было правильного варианта

## Спека

Баг #20 от Александра (19.11.2026, 09:40). Полный текст:

```
дало упражнение где надо было вставить 
This new video game is so ___ that I can't stop playing.

Я вставил addicrive, а правильным ответом оказалось highly (хотя я так понимаю
правильно было вообще highly addictive) но варианта такого не было
```

Это вопрос «🔗 Сочетания» — выбор из вариантов, а не ответ текстом. В базе он выглядел так:

```
Какое слово подходит к 'addictive'?
This new video game is so ___ that I can't stop playing.
варианты: highly / addictive / behavior
верный (по базе): highly
```

Подстановка «верного» варианта: «This new video game is so **highly** that I can't stop playing».
Прилагательное заменено наречием — правильного варианта в списке не было. Автор прав.

Приёмка: новый вопрос проходит самопроверку «подставь верный вариант и прочитай предложение»;
негодный отбрасывается, сочетания слова остаются; прогон по базе убирает накопившиеся; на проде
негодных вопросов не остаётся.

## Причина

Вопрос проверялся только на **формат**:

```ts
.refine((q) => q.correct < q.options.length)   // «индекс не вылез за массив»
```

У вопросов по ошибкам самопроверка была (`buildDrillReviewPrompt`: «подставь каждый вариант, оставь
только задания, где ровно один даёт верное предложение»), у сочетаний — нет. Один и тот же класс
задания проверялся по-разному.

## Что сделано

- **`llm/tutor.ts`**: `buildQuizCheckPrompt` + `parseQuizCheck` — отдельная проверка вопроса.
  `QuizCheck` вынесен в тип. Ответ не разобрали — вопрос считается годным (проверка только добавляет
  строгости, её сбой не должен выбрасывать сделанную работу).
- **`ExerciseTutor.checkCollocationQuiz?`** — необязательный метод; роутер делегирует, провайдер без
  него отвечает «годен». Необязательный намеренно: иначе ломались бы все фейки в тестах.
- **`ClaudeCodeEnricher.collocations`** — после генерации проверяет вопрос и при отказе возвращает
  только `items`.
- **`scripts/check-collocation-quizzes.ts`** — разовый прогон по базе, `--dry-run`, `--limit=N`.

## Решения и причины

- **Первый критерий был неверным, и это стоит запомнить.** Я потребовал «ровно один вариант даёт
  грамматически верное предложение» — и проверка отбраковала **91 вопрос из 151**. Среди них годные:
  «sink **into** despair» идиоматичнее, чем «sink **in** despair», но второе не ошибка. Вопрос на
  сочетания как раз и проверяет, какое из допустимых звучит естественнее, — требовать единственно
  верного значит не понимать задание.
- **Критерий сведён к двум точным случаям.** Вопрос негоден, если (1) подставленный «верный» вариант
  даёт бессмыслицу или аграмматику — тогда правильного ответа в списке нет; (2) ответ — само
  проверяемое слово, а не соседнее слово-партнёр. Остальное годно. Стало 34 из 151, и 24 из них —
  старая защита `validQuiz`, которая и раньше скрывала эти вопросы при чтении.
- **Сочетания не удаляются вместе с вопросом.** `items` полезны и без него: человек видит, с чем
  слово употребляется.
- **Негодный вопрос убирается, а не переписывается.** Переписать может только модель, и это новый
  запрос с новым риском; убрать — дёшево и честно.

## Известные ограничения

- **Проверка стоит один лишний запрос к модели** на каждое новое слово с сочетаниями. Для `addictive`
  это оправдано; при массовом добавлении расход вырастет примерно вдвое на этих словах. Квоты
  `draft` это учитывают — генерация сочетаний идёт в фоне.
- **24 вопроса остались в базе, хотя человек их не видит.** Их скрывает `validQuiz` при чтении; скрипт
  тоже пометил их к удалению, но удаляет только `quiz`, а `validQuiz` отбрасывает и без этого.
  Удалять их из базы смысла нет: чтение и так безопасно.
- **`think it over` потерял вопрос**, хотя был содержательный: ответ `thought` — форма самого слова.
  По критерию это «не сочетание», и формально верно, но обидно. Возвращать вручную не стал.
- **Разовые прогоны требуют модели.** Скрипт работает только там, где настроен провайдер и есть
  ключ; в CI он не запускается.
- **Другие типы заданий не проверялись.** `cloze` и `drill` имеют свои проверки (у drill — с самого
  начала, у cloze исправлено в E38).
