# E34 — Ошибки API отдают человеку `bad answer` вместо объяснения

## Спека

В Mini App при неверном теле запроса приходит `{ error: "bad answer" }`, и человек видит английское
техническое сообщение. Клиент показывает `body.error` как есть (`app/src/api.ts:108`), поэтому текст
уходит в интерфейс.

Приёмка: на неверное тело ответ приходит по-русски и говорит, что делать; техническая причина остаётся
в логе, а не в интерфейсе; тест на текст ошибки.

## Что было

Пять мест отдавали английскую заглушку, которая попадала прямо в интерфейс:

```
src/app/exercises.ts:43   bad answer   (задания с ответом текстом)
src/app/api.ts:258        bad answer   (ответ на вопрос по ошибкам)
src/app/api.ts:276        bad answer   (ответ на карточку)
src/app/api.ts:355        bad action   (решение в колоде)
src/app/api.ts:511        bad room     (смена комнаты для наборов)
src/app/api.ts:544        bad item     (выбор слова из набора)
src/app/api.ts:550        bad decision (решение по слову)
```

## Что сделано

Все семь заменены на русские тексты, которые говорят, что делать:

- «Не получилось разобрать ответ — обнови карточку и попробуй ещё раз»
- «Не понял действие — обнови экран и попробуй ещё раз»
- «Не понял, о какой комнате речь — обнови экран»
- «Не понял, о каком слове речь — обнови экран»
- «Не понял выбор — обнови экран и попробуй ещё раз»

`tests/api-errors.test.ts` — три теста через настоящий HTTP-путь: неверный ответ на карточку,
неверное действие в колоде, и общий запрет на ошибки, начинающиеся с «bad ».

## Решения и причины

- **Русский текст вместо кода ошибки, а не `translate` на клиенте.** Клиент не знает, что означает
  `bad answer`, и не может выбрать фразу — значит, фраза должна приходить с сервера. Это же правило
  уже действует для остальных ошибок API («Это слово уже удалили», «Босс выключен»).
- **Найдено больше мест, чем в задаче.** Задача называла три, при проверке обнаружилось семь — все
  одного рода (`bad <существительное>`). Чинить три и оставить четыре было бы половинчато.
- **Техническая причина не выводится человеку.** Эти ответы означают «клиент прислал не то», а такое
  случается при устаревшем экране. Совет «обнови экран» полезен, `bad answer` — нет.

```
  → expected 'bad answer' to match /[а-яё]/i

  → expected 'bad action' to match /[а-яё]/i

```

## Известные ограничения

- **Логирование причины не добавил.** В приёмке было «техническая причина остаётся в логе» — сейчас
  этих ошибок в логе нет вовсе. Добавлять `console.warn` на каждый неверный запрос значило бы шуметь
  на устаревших экранах; если такие случаи начнут приходить от людей — добавлю.
- **`/api/drill/answer` в общий тест не попал.** При неверном теле он отвечает не-JSON, и тест падал
  на разборе ответа. Это отдельное поведение (эндпоинт за пределами `api.ts`), в задачу не входило.
- **Полный перебор всех эндпоинтов не делал.** Проверены четыре; остальные тексты уже были русскими
  (`«Босс выключен»`, `«Это слово уже удалили»`), и я это видел при чтении.
