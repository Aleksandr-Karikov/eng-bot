# E47 — Линтер в проекте и в CI

## Спека

В репозитории нет линтера. `typecheck` проверяет совпадение типов, но не видит необработанных
промисов, `String()` на объекте, мёртвого кода и забытых зависимостей хуков. Требование: линтер
в проекте и в CI, с анализом типов, на весь код с типами проекта.

Приёмка: `npm run lint` проходит на текущем коде; шаг стоит в `ci.yml`; найденные настоящие дефекты
исправлены, а не заглушены.

## Выбор инструмента

Проверялись два: ESLint с `typescript-eslint` (официальный путь) и `oxlint` с бэкендом `tsgolint`.
Решали замером на этом репозитории, одинаковым набором правил (`recommendedTypeChecked`
typescript-eslint) и одинаковыми исключениями:

| | ESLint + typescript-eslint | oxlint + tsgolint |
| --- | --- | --- |
| 372 файла | 17.0 с | **1.2 с** |
| Находки | 23 ошибки, 7 предупреждений | 21 ошибка, 1 предупреждение |
| Правила хуков React в `app/src` | 6 `set-state-in-effect` + `exhaustive-deps` | те же 6 + `exhaustive-deps` |
| Покрытие type-aware правил | 61 из 61 | 60 из 62 |

Взяли oxlint: находки те же, время в 14 раз меньше. Двух отсутствующих правил нам не нужно.
oxlint дополнительно нашёл то, чего в наборе ESLint нет: `no-meaningless-void-operator` на
`void play(...)`, где `play` возвращает `void` — свежий код этой же задачи.

Форматирование не трогали: линтер не переформатирует, `--fix` используется только для безопасных правок.

## Что сделано

**Конфигурация.** `.oxlintrc.json`: анализ типов включён, каталоги правил (style, pedantic) выключены —
включены только правила про ошибки. Исключения по областям:

- `tests/` — выключены `no-unsafe-*`, `unbound-method`, `no-unnecessary-type-assertion`: харнесс
  собирает payload-ы Telegram как `Record<string, unknown>`, а `expect(obj.method)` в vitest — штатный
  приём. Иначе правило ругалось бы на способ тестирования, а не на ошибку.
- `app/src/` — правила хуков React (`rules-of-hooks`, `exhaustive-deps`, `set-state-in-effect`,
  `purity`, `refs` и другие). Только для этой папки: на серверном коде они дают ложные срабатывания
  (`LocalRecognizer` принимается за React-класс).
- `extension/`, `**/*.mjs`, `scripts/docs.mjs` — вне обхвата: у них нет типов проекта. Для `.mjs`
  анализ типов выдаёт 65 ошибок на файл из-за отсутствия tsconfig, а не из-за дефектов.

`scripts`: `npm run lint`, `npm run lint:fix`. В `ci.yml` шаг `npm run lint` стоит первым — он дешевле
тестов и валит сборку раньше.

**Исправлено 17 дефектов** (не заглушено):

- `String(obj)` там, где значение может быть объектом — `[object Object]` вместо пустой строки:
  `speech/stt.ts` (ответ воркера), `llm/enricher.ts` (перевод из ответа модели), `capture/server.ts`
  (ключ расширения из тела запроса, два места).
- `reject(non-Error)` в `capture/server.ts` — причина отклонения промиса теперь всегда `Error`.
- `async`-функция в `setInterval`/`createServer` без обработки отклонения: `meeting-poll-loop.ts`,
  `reminder-loop.ts`, `images/painter.ts`, `capture/server.ts`. Ошибки внутри уже ловились, но
  намерение не было видно — теперь `void tick()` и объяснение в комментарии.
- `src/app/server.ts`: 33 находки об одном — Hono отдаёт тело запроса как `any`. Введён один
  типизированный `readBody()`, который возвращает `Record<string, unknown>`; мусор и не-JSON дают
  пустой объект. Заодно убраны 4 лишних приведения статуса.
- Мёртвый код после E23 (корейский убран): `room` и импорт `getRoom` в `src/app/server.ts` —
  комментарий обещал «язык комнаты», но `withLang` больше нет; `HANGUL`, `USEFULNESS_HINT_PLAIN`,
  `capStem`, `GAP`; ветки `if (true)`/`if (false)` в `check.ts`/`pronounce.ts`.
- `Map` из `new Map()` в `pauses.ts`, `handlers/learn.ts`, `app/api.ts` — присваивание внутри вызова
  стирало тип до `Map<any, any>`, и проверка типов дальше по функции переставала что-либо значить.
- `unbound-method` в `services/words.ts`: `translate.call(enricher, ...)` заменён на прямой вызов.
- 21 неиспользуемый импорт и переменная в тестах и скриптах.
- `await` на синхронном драйвере `better-sqlite3` (`.all()`/`.run()`) — 16 мест в тестах.
- В `app/src`: `onBuy={() => void buy(kind)}` (пропускался аргумент — это была настоящая ошибка
  типов), `setTimeout(() => void refresh())`, IIFE для `onClick`, `Array<string>` вместо `any[]`,
  удалена мёртвая `undo` в `Grammar.tsx`.

**Один приём вместо девяти копий.** `String(call.payload.text ?? "")` повторялся в 9 тестах; добавлены
`textOf()` и `sentTexts()` в `tests/bot-harness.ts`.

## Решения и ограничения

- **7 предупреждений `react/set-state-in-effect` оставлены.** Все — загрузка данных в `useEffect`
  (`Learn.tsx`, `WordPage.tsx`, `Words.tsx`, `TypeCard.tsx`, `bottomButtons.ts`, `useTypeKeyboard.ts`).
  Это принятый в проекте приём; переписывать загрузку на `useSyncExternalStore` ради тишины линтера
  — отдельная задача с собственным риском. Правило стоит как `warn`, а не `error`: сборку не валит.
- **`capture/server.ts` и `createServer(async ...)`** помечены комментарием, а не `eslint-disable`:
  ошибки внутри обработчика ловит его собственный `try/catch`.
- **`lang` в `LlmBackend.ask` остался.** Параметр не используется провайдерами, но его наличие
  закрепляет тест `llm-provider.test.ts` («бэкенд получает английский»); помечен `_lang`.
- **`extension/` не линтуется.** 3500 строк JS браузерного расширения без типов; отдельная задача,
  если понадобится.
- `oxlint-tsgolint` — бинарник на платформу (22 МБ). В `devDependencies`, в продакшене не нужен.

## Проверено

- `npm run lint` — 0 ошибок, 7 предупреждений (все перечислены выше).
- `npm test` — 136 файлов, 933 теста прошли.
- `npm run typecheck` — без ошибок.
- `cd app && npm run build` — собралось (767 модулей).
- `npm run docs:index` и `npm run docs:check` — 47 задач, документы согласованы.
- Проверка на ложные срабатывания: oxlint прогнан на `extension/` и `*.mjs` — 602 находки, все
  из-за отсутствия типов проекта; эти каталоги исключены, а не заглушены.
- Живой бот и продакшен не запускались: изменения касаются типов и обработки ошибок, поведение
  для пользователя не менялось. Тесты Телеграм-слоя идут через `bot-harness`.
