# E11 — Недельная работа трофеев выполняется каждую минуту

## Спека

`sendTrophies` вызывается в тике напоминаний с интервалом по умолчанию 60 секунд, а `collectTrophies`
на каждом вызове читает всю таблицу `trophies`, все комнаты и считает `weekFacts` по каждой. Это
примерно 10 080 прогонов в неделю вместо одного.

Приёмка: недельный расчёт выполняется по признаку закрытой недели, а не по тику; тест проверяет, что
повторные тики в одну неделю не пересчитывают; идемпотентность выдачи трофеев сохраняется.

Подсказка из задачи: «похоже на `rooms.goalReachedWeek` — тот же приём стоит применить».

## Что было до правки

`sendTrophies` звал `collectTrophies` без всякого признака «уже считали». Внутри на каждом вызове:
полное чтение `trophies`, затем по каждой комнате `weekFacts` — а это `goalProgress`, ответы за две
недели с джойнами по `cards`/`words`/`users`, удары босса, участники, `personalStats` на каждого.

Замер на 20 комнатах с активностью (проба, воспроизведена):

```
60 тиков подряд:  старое поведение 1370 ms  |  новое 207 ms  |  разница 6.6x
первый тик: 38 ms  |  каждый последующий: ~3.4 ms
```

## Что сделано

- `src/db/schema.ts` — колонка `rooms.trophies_week` (text, null), назначение описано рядом.
- `drizzle/0061_great_sheva_callister.sql` — сгенерированная миграция: `ALTER TABLE rooms ADD
  trophies_week text`. Схему меняет только она, при старте бота.
- `src/services/trophies.ts`:
  - `CollectTrophiesOptions` — новый интерфейс с `onlyFreshWeeks`;
  - в цикле по комнатам неделя считается **до** `weekFacts`, и комната с совпавшей отметкой
    пропускается немедленно, то есть дорогой расчёт не выполняется вовсе;
  - пустая неделя (`facts.done === 0`) тоже отмечается — иначе она пересчитывалась бы вечно;
  - отметка ставится в конце обработки комнаты, а не до расчёта: падение посередине не оставит
    ложного «уже посчитано»;
  - добавлена `markTrophiesWeek(db, roomId, week)`.
- `src/reminder-loop.ts` — `sendTrophies` передаёт `onlyFreshWeeks: true`, с объяснением в комментарии.
- `tests/boss.test.ts` — два теста: «повторный тик в ту же неделю ничего не пересчитывает и не дублирует
  трофеи» (включая переход на следующую неделю) и «бэкфилл без флага по-прежнему видит прошлые недели».

## Решения и причины

- **Отдельная колонка, а не `goalReachedWeek`.** Поздравление с целью недели и трофеи — разные сообщения,
  и они могут разойтись по времени: цель достигнута в среду, трофеи выдаются в воскресенье. Общая
  отметка заставила бы одно событие блокировать другое.
- **Флаг `onlyFreshWeeks`, включённый только в фоне.** Скрипт `scripts/backfill-trophies.ts` намеренно
  пересчитывает прошлые недели — восемь прогонов по разным датам. Если бы отметка действовала и там,
  после первого прогона бэкфилл перестал бы находить что-либо, и восстановление коллекции сломалось бы
  молча. Флаг по умолчанию **выключен**, поэтому скрипт работает как раньше, без правок.
- **Отметка ставится после работы, а не перед.** Обратный порядок экономил бы те же запросы, но при
  падении посередине комната считалась бы «обработанной», и трофеи за эту неделю потерялись бы навсегда
  — ровно та ошибка, которую исправляла E21 для отметок доставки.
- **Пустая неделя отмечается тоже.** Комната без активности (`facts.done === 0`) не выдаёт трофеев, но
  если её не отметить, `weekFacts` по ней считался бы каждую минуту всю неделю.
- **Идемпотентность не ослаблена.** Прежняя защита — уникальный индекс `(user, kind, week)` плюс
  `onConflictDoNothing` — осталась на месте. Отметка лишь избавляет от повторного расчёта, а не заменяет
  защиту от дублей.

## Известные ограничения

- **Экономия не 10 080×, а примерно 6.6× по времени.** Расчёт всё равно выполняется один раз за неделю
  на комнату плюс чтение списка комнат на каждом тике. Сокращение — по числу дорогих `weekFacts`,
  а не по числу тиков: они по-прежнему происходят, но почти ничего не делают.
- **Отметка не сбрасывается при переезде недели назад.** Если системные часы уедут вперёд, а потом
  вернутся, `trophiesWeek` может оказаться «из будущего», и трофеи за пропущенную неделю не выдадутся
  автоматически. Сценарий экзотический, но ручного сброса нет.
- **Бэкфилл не ставит отметку.** После него фоновая отметка остаётся прежней, и первый фон-тик может
  один раз пересчитать неделю, за которую бэкфилл уже выдал трофеи. Дублей не будет (уникальный индекс),
  но лишний расчёт один раз случится.
- **На проде не замерялось.** Числа получены на тестовой базе в памяти с 20 комнатами. На реальной
  базе (`data/backups/prod-20261115-192301.sqlite`, 19 комнат) порядок величин тот же, отдельного
  прогона не делал.
- **Миграция применится при старте бота.** После деплоя колонка появится сама; на существующих комнатах
  она `NULL`, поэтому первый тик после обновления пересчитает каждую комнату по разу — это ожидаемо.
