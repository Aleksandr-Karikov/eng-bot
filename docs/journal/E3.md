# E3 — Цель недели сжимается от усилений, и глубина не копится

## Спека

Цель недели считалась как `autoGoal(raw) × BASE_WEIGHT`, где `raw` — число ответов прошлой недели.
Усиление поднимает урон за ответ, поэтому для той же цели нужно меньше ответов: `raw` падал, и следующая
цель становилась **меньше**. Человек не «доходил дальше», а откатывался.

Приёмка: цель недели не зависит от усиления; глубина ладдера зависит от личного рекорда и растёт при
росте уровня. Тест: две одинаковые недели с разным уровнем усиления дают одинаковую цель и разную глубину.

Решение владельца: разорвать связь — цель фиксированная, глубина от рекорда.

## Что сделано

- `src/services/goals.ts` — `autoGoal`, `MIN_AUTO_GOAL`, `AUTO_GROWTH` удалены. Вместо них константа
  `DEFAULT_GOAL_HP = 100`: цель недели — `room.weeklyGoal > 0 ? room.weeklyGoal : DEFAULT_GOAL_HP`.
  Прошлая неделя в расчёте цели больше не участвует вовсе. Из `roomReviews` убран счётчик `raw`: он
  стал мёртвым, а оставлять неиспользуемый вход — оставлять путь, по которому связь вернётся.
- `src/bot/texts.ts` — текст `/goal` больше не обещает «цель по прошлой неделе, +10%»: при общей цели
  он говорит «Цель одна для всех — 100 HP», при своей — «Вернуть общую цель — /goal auto».
- `app/src/Progress.tsx` — та же подпись в Mini App.
- `src/db/schema.ts`, `src/services/boss.ts` — комментарии приведены в соответствие: `weekly_goal = 0`
  означает общую цель, а не подбор по прошлой неделе.
- `tests/goals.test.ts` — тест `autoGoal` заменён на проверку константы; тест цели комнаты обновлён
  (цель 100 вместо 140 при огромной прошлой неделе); добавлены два теста приёмки, см. ниже.
- `docs/architecture.md` — в раздел про босса добавлен абзац о фиксированной цели с причинами E3 и E4.

## Решения и причины

- **Фиксированное число, а не «по рекорду комнаты».** Приёмка допускала оба варианта, но рекорд — это
  новая колонка и новая миграция ради числа, которое по смыслу должно быть одинаковым для всех. Ладдер
  боссов уже фиксирован (`LADDER_BASE_HP = 25`, `tierHp`), и именно он отвечает за «доходить дальше»;
  цель недели — это база для монет и трофеев, и ей довольно быть постоянной.
- **100 HP, а не 50 и не 200.** Замер по копии прод-базы `data/backups/prod-20261115-192301.sqlite`:
  цель недели по прежней формуле составляла 100 HP в 13 неделях из 17 и 2220–3980 HP в остальных
  четырёх. То есть у активных комнат босс был недостижим в принципе. 100 HP ≈ 50 ответов «Помню» —
  это ровно тот объём, с которым комната справляется, а не упирается.
- **`raw` удалён, а не оставлен «на будущее».** Счётчик ответов был единственным входом, через который
  связь цели с прошлой неделей возвращалась бы при любой следующей правке.
- **Тексты поправлены вместе с формулой.** Оставить в `/goal` фразу «подобрана по прошлой неделе» при
  фиксированной цели значило бы врать человеку в интерфейсе — это часть той же задачи, а не косметика.

## Проверки

```
npx vitest run tests/goals.test.ts  → 6 tests passed
npx vitest run                      → 119 files, 834 tests passed
npx tsc --noEmit                    → чисто
cd app && npm run build             → собралось
```

Тесты проверены на старом коде (`git stash push src/services/goals.ts`), падают по существу:

```
× одинаковый урон даёт одинаковую цель при разном усилении
  → expected 440 to be 220
× прошлая неделя с преобладанием «Забыл» не раздувает цель
  → expected 440 to be 100
× counts this week's reviews ... → expected { target: 140, … } to deeply equal { target: 100, … }
```

Первая строка — это ровно дефект E3: тот же урон (400 HP) давал усиленному человеку цель вдвое меньше.

## Известные ограничения

- **Исторические числа в `/goal` изменились.** Комнаты, у которых была автоцель, увидят 100 HP там, где
  раньше стояли 2220–3980 HP. Это цель изменения, но выглядит оно как «босс стал слабее»; отдельного
  объявления в интерфейсе («цель изменилась с …») нет.
- **Ручные цели не тронуты.** В проде таких нет (проверено: все 19 комнат с `weekly_goal = 0`), но
  если кто-то задал `/goal` руками, у него всё осталось как было — это осознанно.
- **Глубина ладдера от рекорда не сделана — и не нужна.** Проверено по коду: `bossOf` уже берёт базу
  из `LADDER_BASE_HP` (фиксированную), а не из автоцели, и раунды считаются от урона недели через
  `bossRound`. Замер: 100 HP урона → 3 добитых босса, 400 HP → 6, 2012 HP → 21. То есть глубина растёт
  от силы, как и требует приёмка, и отдельной колонки «рекорд» не требуется.
- **`BASE_WEIGHT` остался экспортом.** Он больше не участвует в цели, но используется в документации
  и как ориентир цены ответа; удалять его — отдельная уборка мёртвых экспортов.
