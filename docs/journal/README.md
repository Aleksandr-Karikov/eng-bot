# Журналы задач

Один файл на закрытую задачу: `E<номер>.md`, где номер совпадает со строкой в [PLAN.md](../PLAN.md).
Журнал пишется до того, как задача отметится закрытой, и остаётся после — это единственное место, где
хранятся решения и причины.

## Разделы

```md
# E7 — Выключение BOSS_ENABLED=0 меняет числа

## Спека

Требование так, как оно было сформулировано до правки.

## Что сделано

Что изменилось и где. Пути к файлам, а не пересказ кода.

## Решения и ограничения

Что выбрали и почему. Что сознательно отложили и чего ждём.

## Проверено

Фактические команды и результат. Непроверенное не записывать как проверенное.

## Известные ограничения

Что осталось за рамками задачи.
```

## Правила

- Не пишите то, что не проверяли: «проверено» — это выполненная команда или пройденный сценарий.
  Отказ из-за окружения (занятый порт, недоступный внешний API, второй запущенный `npm test`) называйте
  отдельно — это не результат правки.
- Числа, которые меняются с каждым коммитом (тестов, таблиц, пользователей), в журнал не переносите
  как обещание: актуальное показывают `npm test` и `/status`.
- Решение, оставшееся только в переписке, потеряется. Причина, по которой сделали именно так, важнее
  списка изменённых файлов.
- Ссылка на журнал добавляется в закрытую строку плана: `[журнал](journal/E7.md)`.
  `npm run docs:check` проверяет, что ссылка есть и файл существует.
