# План проекта

Добавляй задачу, когда появится требование к проекту. Открытая строка содержит спеку, приёмку и
текущее состояние; после завершения подробности переносятся в `journal/E<номер>.md`. Номер не
переиспользуется. Создавай следующий свободный `E<номер>`.

Формат открытой задачи:

```md
- [ ] **E1** — Название. **Спека:** цель, сценарий, состояния, данные и права (если применимо). **Приёмка:** наблюдаемый результат и необходимые проверки. ➡️ **Сейчас:** что известно, что мешает, следующий шаг.
```

Правила ведения — в [CONTRIBUTING.md](CONTRIBUTING.md). Индекс [INDEX.md](INDEX.md) генерируется
командой `npm run docs:index`; руками его не правь.

## Задачи

Первый блок — расхождения между задуманным и работающим, найденные разбором босса недели
([boss-next-plan.md](boss-next-plan.md) — источник разбора, история и гипотезы, а не список задач).
Каждый пункт сверен с кодом; ссылки на числа стенда и живого прогона остаются в исходном документе.

- [ ] **E1** — Кнопка «Ударить босса» не работает при настройке по умолчанию. **Спека:** запас урона `bankDamage` по умолчанию выключен, поэтому `damageBalanceDeci` считает баланс только по `review_logs.banked = true` и возвращает 0. `reserveHit` получает `available = 0`, `hit.spend = 0`, кнопка ручного удара отрисовывается `disabled` и без подсказки, почему. Человек видит главное действие боя мёртвым и не понимает, что для него нужно включить «Копить урон». **Приёмка:** при выключенном «Копить урон» кнопка либо работает на небанковских ответах, либо явно объясняет и ведёт к нужной настройке; тест `tests/combat*.test.ts` фиксирует выбранное поведение, экран босса проверен в Mini App. ➡️ **Сейчас:** поведение подтверждено по коду (`src/services/combat.ts`, `src/services/combat-ledger.ts`, `app/src/Boss.tsx`). Решение за владельцем: менять экономику запаса или только объяснение на экране.
- [ ] **E2** — «Забыл» возвращает карточку через минуту и бесконечно кормит босса уроном. **Спека:** FSRS отдаёт `again` через 1 минуту, а `answerWeight("again")` равен 1, поэтому одна карточка даёт HP без предела. Награждаются нажатия, а не память, и цель следующей недели при этом растёт. **Приёмка:** повторные «Забыл» по одной карточке не дают неограниченный урон; ограничение названо в задаче и покрыто тестом, который падает при возврате старого поведения. ➡️ **Сейчас:** интервал измерен прогоном на `src/srs/srs.ts` (again → 1 мин, hard → 6, good → 10, easy → 11520). Нужно решение по способу ограничения: окно, суточный лимит на карточку или вес по числу повторов подряд.
- [ ] **E3** — Цель недели обесценивает усиления. **Спека:** `target` считается от числа ответов прошлой недели (`total(prev.raw)`), а усиление поднимает урон за тот же ответ. Чем выше уровень силы, тем меньше ударов нужно, то есть усиление само себя обесценивает и бой становится тем легче, чем дольше играешь. **Приёмка:** соотношение «цель / средний урон» остаётся постоянным при росте уровня; тест на `goalProgress` проверяет, что усиление не меняет число ударов до победы. ➡️ **Сейчас:** подтверждено по `src/services/goals.ts`. Правка формулы меняет исторические числа в `/goal`, поэтому нужно явное решение владельца о способе нормализации.
- [ ] **E4** — Честность наказывается: «Забыл» повышает цель следующей недели. **Спека:** `raw` в `roomReviews` считает все ответы подряд, включая `again`. Ошибки раздувают цель следующей недели, поэтому врать «Помню» выгоднее, чем признаться. **Приёмка:** цель растёт только от ответов, отражающих прогресс, либо правило названо явно; тест покрывает неделю с преобладанием `again`. ➡️ **Сейчас:** подтверждено по `src/services/goals.ts`. Связана с E3: обе правят одну формулу, их разумно свести в один блок.
- [ ] **E5** — «Уже знаю» даёт максимальный базовый урон без проверки. **Спека:** `markKnown` отправляет `easy` для карточки в состоянии `New` с `reps = 0`, то есть 3 HP за нажатие — максимум базовой таблицы без усилия. Ограничение новыми словами не даёт эксплойта, но перекашивает вклад между участниками. **Приёмка:** решение либо оставляет поведение и объясняет его в интерфейсе, либо требует проверки; тест фиксирует выбранное правило. ➡️ **Сейчас:** подтверждено по `src/services/review.ts` и `src/services/goals.ts`. Продуктовый вопрос: считать ли «уже знаю» честным вкладом в общую цель.
- [ ] **E6** — Неделя считается по одному поясу, напоминание приходит по другому. **Спека:** `rooms.timezone` заполняется поясом автора при создании и по умолчанию `Asia/Novosibirsk`, а у пользователя пояс по умолчанию `Europe/Moscow` и напоминание в 20:00 считается по поясу пользователя. В комнате с НСК-поясом напоминание «последний шанс» приходит после фактического сброса недели. Трофеи «ночной» и «ранняя птица» тоже считают часы по поясу комнаты для всех участников. **Приёмка:** правило пояса описано одним местом и совпадает для недели, напоминания и трофеев; тест покрывает участника в одном поясе и комнату в другом. ➡️ **Сейчас:** подтверждено по `src/services/digest.ts`, `src/services/trophies.ts`, `drizzle/0055_cool_speed_demon.sql`, `src/db/schema.ts`. Нужно решить, чей пояс главный для напоминаний — личный или комнатный.
- [ ] **E7** — Выключение `BOSS_ENABLED=0` меняет числа, вопреки обещанию ранбука. **Спека:** `reviewDamage` считает урон с усилением независимо от `active`, а `banked` сбрасывается в `false`. `roomReviews` кладёт в прогресс только записи с `banked = false`, поэтому при выключении режима банковские ответы попадают в `/goal`, а при включении — нет. Комментарий в `src/services/boss.ts` и `docs/server-runbook.md` обещают «те же числа». **Приёмка:** выключение режима не меняет прогресс `/goal`, либо обещание в коде и ранбуке исправлено; тест про две одинаковые недели с разным флагом. ➡️ **Сейчас:** подтверждено по `src/services/review.ts`, `src/services/goals.ts`, `src/services/boss.ts`. Правка ранбука входит в ту же задачу, отдельной не заводить.
- [ ] **E8** — Владелец личного словаря получает «Герой недели» сам о себе. **Спека:** `weeklyReportText` берёт первую строку таблицы как героя недели; в личной комнате первая строка — её единственный участник, и поздравление с победой над собой приходит ему же в личку. **Приёмка:** при одном участнике строка героя не выводится; тест на дайджест личной комнаты. ➡️ **Сейчас:** подтверждено по `src/bot/texts.ts` и `src/services/digest.ts`. Комнат с одним участником много, это больше, чем косметика.
- [ ] **E9** — Mini App при выключенном режиме показывает неверный экран. **Спека:** сервер отдаёт `enabled`, но клиент его не читает: при `enabled: false` и отсутствии `boss` показывается «Боссу нужна комната» с советом `/room` вместо честного «режим выключен». **Приёмка:** выключенный режим и отсутствие комнаты различаются на экране, каждый ведёт к правильному действию; тест на `app/src` и проверка экрана. ➡️ **Сейчас:** подтверждено по `src/app/api.ts` и `app/src/Boss.tsx`: `data.enabled` объявлен в типах, но не используется.
- [ ] **E10** — Контент экрана босса уезжает под системную панель. **Спека:** у `.screen` нижний отступ 96 px и `env(safe-area-inset-bottom)` у панели, а `.boss-screen` перебивает отступ на 24 px при той же специфичности и `safe-area` не содержит. **Приёмка:** на устройстве с home indicator контент не перекрывается; проверено на узкой ширине, правка отражена в `app/src/styles.css`. ➡️ **Сейчас:** подтверждено по `app/src/styles.css`. Дешёвая правка, но требует проверки на реальном устройстве.
- [ ] **E11** — Недельная работа трофеев выполняется каждую минуту. **Спека:** `sendTrophies` вызывается в тике напоминаний с интервалом по умолчанию 60 секунд, а `collectTrophies` на каждом вызове читает всю таблицу `trophies`, все комнаты и считает `weekFacts` по каждой. Это примерно 10 080 прогонов в неделю вместо одного. **Приёмка:** недельный расчёт выполняется по признаку закрытой недели, а не по тику; тест проверяет, что повторные тики в одну неделю не пересчитывают; идемпотентность выдачи трофеев сохраняется. ➡️ **Сейчас:** подтверждено по `src/reminder-loop.ts` и `src/services/trophies.ts`. Похоже на `rooms.goalReachedWeek` — тот же приём стоит применить.
- [ ] **E12** — Победа в чате звучит как отчёт по цели, добивающий удар не называется. **Спека:** `finalBlow` считается в `src/services/boss.ts` и уходит в Mini App, но в чат не попадает: `goalReachedText` перечисляет только счёт и лидера. Комнату никто не поздравляет с добиванием, а сообщение уходит всем участникам, включая тех, кто режим выключил. **Приёмка:** в чат приходит текст с добивающим ударом и фазой; выключившим режим сообщение не уходит; тест на текст и на фильтр получателей. ➡️ **Сейчас:** подтверждено по `src/services/boss.ts`, `src/bot/texts.ts`, `src/reminder-loop.ts`.
- [ ] **E13** — Измерить эффект режима босса. **Спека:** `grep boss` по аналитике не даёт совпадений, поэтому эффект режима неизвестен и любая новая механика — предположение. Нужен минимум: таблица `boss_events(user_id, room_id, kind, week, dedupe, at)` с `kind` из `seen|open|hit|buy|win`, уникальный индекс `(user_id, kind, dedupe)`, запись только `onConflictDoNothing`; пять чисел в `/status` — экспозиция, открытия, ударившие, купившие, вернувшиеся; дата переключения `users.mode_boss` для сравнения окнами по 14 дней. Попутно убрать чтения без `where` в `trainerReport` и `sourceSummary` и сузить `withCombatLock` до денежных операций: сейчас он сериализует все ответы всех людей в одном процессе. **Приёмка:** `/status` показывает пять чисел, события не дублируются при повторной записи, схема и миграция сгенерированы (`npm run db:generate`) и закоммичены. ➡️ **Сейчас:** подтверждено по `src/reminder-loop.ts`, `src/services/combat-ledger.ts`, `src/bot/handlers/status.ts`. Отдельный вопрос: A/B-платформы нет, сравнение делается по переключениям на тех же людях.
