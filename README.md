# eng-bot

Telegram-бот для совместного заучивания иностранных слов с друзьями: английский и корейский.

Инструкции для агентов и правила работы с кодом — в `AGENTS.md`.
Что открыто и что считается сделанным — `docs/PLAN.md`; как вести задачу и журнал — `docs/CONTRIBUTING.md`.
Текущий продакшен на VPS: конфигурация, повторная установка и восстановление —
`docs/server-runbook.md`.

## Запуск

1. Node.js ≥ 20.12.
2. Залогиниться в Claude Code на этой машине (`claude`): по умолчанию бот берёт переводы через Claude Agent SDK, API-ключ не нужен.
3. Создать бота у @BotFather, скопировать `.env.example` в `.env` и вписать `BOT_TOKEN`.
   Privacy mode в группах можно оставить включённым — бот работает через команды и ответы на свои сообщения.
4. `npm install`
5. `npm start` (или `caffeinate -i npm start`, чтобы мак не засыпал).

Проверить подсказки отдельно: `npx tsx scripts/try-enrich.ts serendipity`.

## Модель: Claude Code или OpenRouter

По умолчанию считает локальный Claude Code. Второй вариант — OpenRouter, если хочется модель в облаке
или Claude Code под рукой нет: в `.env` нужны `OPEN_ROUTER_API_KEY` и `OPENROUTER_MODEL`
(имена моделей у OpenRouter свои — `anthropic/claude-haiku-5.5`, список на openrouter.ai/models).

Переключаться можно **на лету, без перезапуска** — `/llm` в боте (для `ADMIN_TELEGRAM_ID`) или:

```bash
npx tsx scripts/llm.ts                       # кто считает сейчас
npx tsx scripts/llm.ts openrouter --check    # переключить и сразу проверить живым запросом
npx tsx scripts/llm.ts claude-code           # вернуться назад
```

Выбор переживает перезапуск (`data/llm-provider`). Уже начатые запросы дорабатывают на прежнем провайдере.
Модели для запоминалок и проверок задаются отдельно: `OPENROUTER_MNEMONIC_MODEL`, `OPENROUTER_CHECK_MODEL`
(не заданы — берётся основная).

Если Claude Code не залогинен, он отвечает `Not logged in · Please run /login` — тогда бот работать не будет,
пока не выполнишь `claude` и не войдёшь, либо не переключишься на OpenRouter.

## Языки

У каждой комнаты свой изучаемый язык; интерфейс бота всегда русский. `/lang` переключает язык в один тап
и возвращает в последнюю комнату этого языка.

- 🇬🇧 **Английский** — транскрипция IPA, два варианта произношения (UK/US), `/pron` проверяет произношение.
- 🇰🇷 **Корейский** — романизация вместо IPA, один вариант произношения, слова хранятся в словарной форме.
  Озвучка идёт голосом Yuna на Mac и через espeak-ng на Linux; `/pron` пока только для английского.

Промпты подставляют язык сами (`src/lang.ts`), английские тексты при этом не меняются — это закреплено
фикстурой `tests/fixtures/prompts-en.json`.

## Ежедневный опрос о встрече

Владелец группы отправляет команду от своего имени в чате с ботом:

```text
/meetpoll 12:00 Asia/Novosibirsk | 18:00 | 19:30 | Не смогу
```

Бот будет публиковать опрос каждый день в 12:00 по Новосибирску. Участники могут отметить все удобные варианты и видят, кто как проголосовал. Дата указана в самом опросе. Если часовой пояс в команде пропущен, бот использует пояс из личных настроек владельца.

`/meetpoll` показывает расписание и варианты. Повторная настройка меняет их, а `/meetpoll off` выключает опрос. Если бот был недоступен в назначенное время, он попробует отправить опрос после запуска в тот же день.

## Наблюдение за ботом

Отдельного сторожа в проекте нет: прежний `scripts/watchdog.ts` остался с маковых времён, на VPS
не запускался и работать там не мог (он искал процесс по шаблону `tsx/dist/cli.mjs`, а юнит запускает
`node --import tsx`, и перезапускал через `launchctl`, которого на Linux нет). Удалён вместе с Mac-скриптами.

За живучесть процесса отвечает systemd (`scripts/server/eng-bot.service`):

| Что | Как | Что будет |
|---|---|---|
| Падение процесса | `Restart=always`, `RestartSec=5` | бот поднимется через 5 секунд |
| Бесконечный цикл падений | `StartLimitIntervalSec=300`, `StartLimitBurst=10` | после 10 падений за 5 минут юнит остановится, а не будет крутиться вечно |
| Долгая остановка | `TimeoutStopSec=45` | закрыть серверы и TTS-процесс успевает, long polling ждёт до 30 с |

**Чего это не ловит:** случай «процесс жив, а polling умер» (2 ноября 2026 бот висел, логи не писались,
а Telegram не получал `getUpdates`). Такой отказ автоматически не наблюдается — проверять руками:

```bash
systemctl status eng-bot.service          # жив ли процесс и когда перезапускался
curl -s "http://127.0.0.1:8788/app/" -o /dev/null -w "%{http_code}\n"   # отвечает ли Mini App
```

Ещё одна проверка — `/status` в боте (для `ADMIN_TELEGRAM_ID`): там видно время старта и свежие числа.

Пульс `data/heartbeat` по-прежнему пишется раз в 30 секунд, но читать его некому — оставлен как
дешёвая диагностика: по времени файла сразу видно, когда процесс перестал работать.

## Картинки-ассоциации (локальный FLUX)

Кнопка «💡 Запоминалка» на карточках → под запоминалкой «🖼 Нарисовать»: Claude описывает сцену, локальный
FLUX.1-schnell рисует её (~20 с, пик памяти ~12 ГБ, по одной картинке за раз), картинка кэшируется на слово.

1. Поставить генератор: `tools/imagegen/README.md` (окружение `tools/imagegen/.venv` с `mflux` и `pillow<13`).
2. В `.env`: `IMAGES_ENABLED=1` (путь к генератору — `MFLUX_BIN`, по умолчанию `tools/imagegen/.venv/bin/mflux-generate`).
3. Перезапустить бота. Выключить — `IMAGES_ENABLED=0` и перезапуск: кнопка «🖼» пропадёт, остальное работает.

## Статистика

`npx tsx scripts/stats.ts` — сводка за 30 дней (только чтение): «Забыл» по ступеням, забывание новых слов
при первом показе, трудные слова, активность по людям, частые темы ошибок /check.

|---|---|---|
| Бот (grammY, long polling), серверы Mini App и приёма слов | `src/` | — |

| Распознавание речи Whisper | `tools/stt/` | `tools/stt/README.md` |
| Частотность слов (wordfreq) | `tools/wordfreq/` | `tools/wordfreq/README.md` |

Python-окружения (uv) в git не попадают: без них соответствующие возможности просто выключаются,
бот продолжает работать.

## Разработка

- `npm test` — тесты (SQLite in-memory)
- `npm run typecheck`
- `npm run db:generate` — после изменения `src/db/schema.ts`
- `AGENTS.md` — инварианты архитектуры, соглашения тестов, эксплуатация

База лежит в `data/eng-bot.sqlite` (WAL); согласованный бэкап живой базы делается через SQLite backup API.

## Ошибки

Пользователи сообщают о проблемах командой `/bug` — она уходит админу (`ADMIN_TELEGRAM_ID`) вместе с
перепиской и хвостом логов. Посмотреть открытые и закрыть: `npx tsx scripts/bugs.ts`.

Админ видит, чем бот работает прямо сейчас, командой `/status`: провайдер и модели, рисуются ли картинки
и идёт ли фоновая генерация, какие ключи заданы (сами ключи не показываются — только «да/нет»), что
установлено на машине и какие порты слушаются. Это снимок на момент запуска, а не чтение `.env`.
